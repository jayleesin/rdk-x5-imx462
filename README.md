# RDK X5 IMX462 source and integration recipes

A single-mode IMX462 sensor plugin for **RDK X5, 1920 × 1080, 20 fps, RAW12 RGGB, two MIPI lanes**. This public edition contains the sensor source, register tables, project-authored integration settings, local reproduction tools, and validation summaries.

The plugin runs in user space through D-Robotics `libcam`. It uses the board's existing camera kernel drivers and ISP runtime. It is not a replacement kernel driver, ISP engine, or complete RTSP application.

## Analysis provenance and REA usage

This port was developed through analysis of the CM4 `imx290.ko` module, comparison with the pinned Raspberry Pi IMX290/462 driver source, and implementation and testing on RDK X5. **REA 6.7.0 was used in this workflow for ELF artifact identification and integrity verification.**

- **REA scope:** the safe artifact graph provider inspected the module and verified its SHA-256. Native decompilation engines were not configured, so no REA decompilation was performed.
- **Register extraction:** ELF symbols and register tables were extracted using `pyelftools`. All 41 IMX462-specific register/value pairs matched the pinned public driver source.
- **X5 implementation:** the extracted information and source comparison informed the X5-native `libcam` sensor plugin. The plugin was implemented and validated separately; it was not automatically generated by REA or made by copying the CM4 kernel module onto X5.

The ISP baseline comes from the separately supplied X5 IMX219 tuning profile; REA did not produce IMX462-specific ISP calibration. Tool scope, module identity, and evidence hashes are recorded in [provenance.json](provenance.json). Original binary-analysis logs and the CM4 module remain outside this public edition.

## Tested environment

- RDK X5, RDK OS 3.5.0, Ubuntu 22.04.5, Linux 6.1.83, AArch64
- `hobot-camera 3.1.1-20260409105913`, GCC 11.2.0
- libcam headers at commit `52bbff4cc77ccdff1182c710590ba17dddd6ee73`
- I²C bus 6, sensor address `0x1a`, MIPI RX 0, two lanes
- A module with a nominal 37.125 MHz reference clock; host MCLK disabled
- No GPIO power/reset switching or IR-cut control

The module clock was not measured electrically. Other boards, modules, clocks, SDK versions, and modes require separate validation.

## Local use

Verify the public files first:

```sh
python3 scripts/verify_public_release.py
```

Provide the matching SDK headers and runtime separately, subject to their applicable terms:

```sh
INC=/absolute/path/to/x5-libcam-inc sh scripts/build.sh
```

The output is `build/libimx462.so`. Building does not install files, initialize the camera, or restart services. Generated files belong in ignored local directories; this release does not clear them for redistribution.

For a matching, separately obtained SDK installation:

```sh
mkdir -p build
python3 scripts/make_isp_profile.py \
  /usr/hobot/lib/sensor/imx219_1920x1080_tuning.json \
  build/imx462_tuning.json
python3 scripts/make_pipeline_config.py \
  /app/multimedia_samples/vp_sensors/imx219/linear_1920x1080_raw10_30fps_2lane.c \
  build/linear_1920x1080_raw12_20fps_2lane.c
```

Both tools validate the input and output hashes and refuse to overwrite existing files. They do not download or bundle vendor data. Access to an input file does not itself grant modification or redistribution rights; use it under the applicable SDK permissions.

Read [build details](docs/BUILD.md), [mode settings](docs/CONFIGURATION.md), and [backup/install/rollback steps](docs/INSTALL.md) before integration. Copying the plugin alone does not create an RTSP service or select this sensor configuration in an application.

## Validation and image-quality status

The sensor source has reproduced the private device binary byte-for-byte in the tested environment. The local ISP and pipeline recipes reproduce the tested configuration files exactly. Reproducibility is a technical result, not a redistribution license.

A previous full-system RTSP/TCP run decoded **864,021 frames over 43,201 seconds**, at approximately **19.999961 fps**, with no detected sensor/frame/RTP-packet loss or service restarts. It used one LAN PC and a particular FFmpeg/server configuration; see [validation scope](docs/VALIDATION.md).

**ISP color calibration remains incomplete.** The tested profile is an IMX219 baseline with metadata changes only. It is not an IMX462-specific AWB, CCM, lens, noise, or IR calibration. A purple tint was observed in low light. The direct fluorescent-lamp view is an untested hypothesis; bright-light and low-light color validation has been deferred. Transmission stability does not establish normal color reproduction.
